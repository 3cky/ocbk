# sim/slot — the МПИ expansion-bus oracle

The pinned contract for `src/bus/qbus_slot.sv`, the slave-only bridge that puts
the internal Q-bus on the physical cartridge-slot pins so a real BK expansion
module — an **SMK512** — can attach through the passive adapter. Run with
`./run.sh` (part of `make sim`) or `./run.sh --mutate`.

The connector this bridges to is traced pin-by-pin in
[doc/dev/mpi.md](../../doc/dev/mpi.md); read that first. Nothing in this oracle
is a replica: the bridge under test is the shipped module, the reply re-timing
is the shipped `bk_rply`, and the thing on the far side behaves like the board
that will actually be plugged in.

## The reference

There is no netlist and no emulator to diff against — BkEmu models the SMK512 as
an internal class, not as a bus participant, so it says nothing about wire
behaviour. The authority here is therefore **the traced schematic**
(`doc/bk0011m.sch`, via the `pcad` MCP) for what the connector carries and where
a module's reply joins, plus the two standing bus rules this design already
enforces everywhere else:

- **the reply re-timing rule** — an external module's RPLY lands on the bus net
  **before** D8:B, the flop `src/bus/bk_rply.sv` models, so the slot needs its
  own instance and the internal slaves must not get a second one;
- **the RMW rule** (`CLAUDE.md`, `doc/dev/gotchas.md`) — a slave FSM returns to
  idle on **strobes-idle**, never on SYNC-rise.

## The legs

| leg | what it pins |
|---|---|
| **module attached** | every sub-test below |
| **empty connector** | the module never replies. Every slot access must bus-time-out to trap 4 and the machine must keep running — the bridge must not invent a reply out of a floating, unterminated pin |
| **DIP 8 stand-down** | a real module **is** attached and answering, but DIP 8 also selects the internal SMK512. The bridge must stand down completely, checked structurally: `rom_dsl_vec` stays 0 and `slot_rd` never sets |

## Sub-tests (the attached leg)

| § | what it pins |
|---|---|
| 1 | **DATI** — the module's presets read back. The model presets a per-word value, so a wrong address on the pins shows up as wrong *data*, not as a missing reply |
| 2 | **DATO** — word write, read back |
| 3 | **DATOB** — both byte lanes, then a word read back: the dual-purpose WTBT (write flag at SYNC, byte flag at DOUT) across the bridge |
| 4 | **DATIO** — `INC @#reg`, read-modify-write under one held SYNC. **The CLAUDE.md RMW rule** |
| 5 | **qbto** — a read of an address neither ocbk nor the module decodes gets no reply at all → trap 4 |
| 6 | **deselect, both directions** — the module asserts BAS10 through its own control register and answers in the BASIC region; then releases it and ocbk's ROM answers again. Checked both ways so a stuck-asserted deselect cannot pass |

## Two checks that had to be structural

Both are the *"every sim still passes"* failure class from
[gotchas.md](../../doc/dev/gotchas.md), and neither is observable behaviourally.
They are the reason this oracle reaches into `u_slot.g_on` rather than only
watching the bus:

- **Pin driver overlap.** The bridge and the module must never drive `pSltAd`
  together. The overlap window is the module's data hold *after* DIN rises, by
  which point the CPU has already sampled — so the resulting X never reaches
  anything the program can see. On the board it is 16 lines of push-pull CMOS
  against a 5 V driver.
- **Inward claim.** The bridge must only take data inward from a cycle the
  module actually claimed. On this active-low wired-AND bus an extra driver of
  all-ones is the **identity element**, so driving `ad_n` from a floating
  connector changes no value — until a glitch on an unterminated pin makes it
  silent corruption of an *internal* read.

## What this oracle does NOT own, deliberately

- **Timing.** It is data-checking, not a golden. The slot has no calibration
  target — an external module owns its own access time and simply replies later
  — so there is no `N_SLOT` to fit. `sim/smktime`'s recipe would apply if one
  ever appears.
- **BK-0011M.** The bk10 leg is the one that matters: MON10/BAS10 are the real
  BK-0010 + SMK512 combination, and a real BK-0011M connector has **no pin** for
  any of the three deselect lines (XT3 has no A14/B1/B6). `qbus_slot` model-gates
  them so a module cannot deselect a ROM the real machine could not; that gate
  is not exercised here.
- **Interrupts, DMA and the IAK chain.** Out of scope for the slave-only
  increment — the bridge has none of them yet.
- **Electrical anything.** Rise times, termination and the clamp are hardware
  measurements, not sim. See mpi.md's termination note; that measurement is the
  gating item before bring-up.

## Mutations

Six, ids **S1–S6**, run by `./run.sh --mutate`. Each is an anchored `sed`
against a **copy** of the real RTL; a sed that fails to apply is a **hard
error** (the anchor moved, so the mutation is silently testing nothing) — the
`sim/evnt` idiom.

| id | what it breaks |
|---|---|
| S1 | outward AD not held off through the module's data hold (pin contention) |
| S2 | **the original stub bug** — AD released until after SYNC falls, so a real slave latches its address with no setup |
| S3 | inward AD driven on every read, not only a claimed one |
| S4 | the module re-arms on SYNC-rise instead of strobes-idle — the DATIO write half is lost |
| S5 | the host ROM still replies in a deselected region (two drivers, one address) |
| S6 | the slot does not stand down for DIP 8 |
